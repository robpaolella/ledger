## How it was done

- Launched with the verify skill on a fresh throwaway database, then driven by script through Chrome (puppeteer-core, one browser profile per role) with real sign-in as owner (John), admin (Jane) and the limited member. Light or dark is set the way the app saves it (`ledger-theme`), then the page is reloaded. No token was injected and no data was edited.
- Sizes: 390×844 and 1440×900 (read back from the page).
- Failed and slow loads were made by blocking or holding the page's own request at the browser (the server was never changed). The two-step sign-in screen was reached by answering the sign-in call locally, as part A did; everything else is the real server.
- Tap sizes were measured by probing the page with `elementFromPoint` around each control, so invisible tap areas count. That is why a control with a 20px text box and a 44px tap area passes.
- Destructive steps stop at their confirmation (delete asset, unsplit); Update balance was never saved. The sample data is unchanged.
- Light and dark were both run for every check. Screenshots are kept for both themes where the look matters; for the tap-size rows (#340, #353) the dark ones are kept too but add nothing beyond the measurements. Admin was run for the findings that part A found for admin (#341, #349, #350, #352, #353); the member for #342, #343–#345, #331, #349, #351.
- Screenshots are in `screenshots/recheck/a/`, named `<issue>-<page>-<role>-<theme>-<width>.png`. Sample data only.
